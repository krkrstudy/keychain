# 钥匙串

一个简洁的共享密码库。网页托管在 GitHub Pages，后台负责加密资料同步和管理员权限验证。无需 GitHub 授权令牌。

站点：https://krkrstudy.github.io/keychain/

## 使用

1. 所有人使用管理员提供的查看账号和查看密码登录。
2. 普通查看者可以显示、复制账号密码；点击“刷新”获取最新资料。
3. 管理员登录后，点击“管理员”，输入独立管理密码，即可添加、编辑、删除账号。
4. 保存后资料加密同步到后台，其他设备点击“刷新”即可看到。
5. 结束后点击“锁定”。5 分钟无操作自动锁定。刷新网页也会清除登录状态；管理权限最长有效 1 小时。

## 手机安装与离线使用

联网登录后，点击页面底部“保存离线副本”，等待“已保存，可离线解锁”。iPhone 在 Safari 分享菜单中选择“添加到主屏幕”；安卓在 Chrome 菜单中选择“安装应用”或“添加到主屏幕”。主屏幕应用首次打开时，联网登录并再保存一次，确认状态后再断网使用。部分系统会将主屏幕应用和浏览器的数据分开保存。

断网后仍需输入查看账号和密码，可显示、复制保存的账号资料。离线时仅查看；新增、编辑、删除和刷新需要联网。恢复网络后点击“刷新”，已有离线副本会自动更新。离线副本是本设备最后保存的版本，不保证包含其他设备的最新修改。

“清除离线副本”只移除本设备的加密副本，不删除后台账号。浏览器清理站点数据、空间不足或系统回收也可能移除副本。网页升级会提示“更新网页”；更新时先锁定，再重新加载。每次修改静态资源都必须递增 `sw.js` 中的缓存版本。

查看密码和管理密码单独交付，不在仓库内。不要向普通查看者分享管理密码。

## 数据与权限

业务账号名称、账号和密码全部由浏览器使用 AES-256-GCM 加密后保存在 Sites 后台的 D1 数据库。查看账号和密码通过 PBKDF2-SHA-256（600,000 次）派生解密密钥；后台没有该解密密钥。每次保存使用随机 IV。

管理员密码与查看密码独立，管理员密码通过 HTTPS 发送给后台进行验证。后台保存随机盐和密码校验值，不保存明文管理密码。初始管理密码由高强度随机数生成。错误尝试限流、会话有效期和每次写入权限都由服务端检查，无法通过显示隐藏按钮绕过。会话仅保存在当前页面内存中；数据库只保存会话摘要。锁定会请求撤销当前会话，断网时以服务端到期时间为准。

多设备保存使用版本号防止静默覆盖。网络失败会明确报错。查看密码、管理密码、业务明文、解密密钥和管理会话均不写入浏览器持久存储。离线保存为用户主动操作，只将 AES-GCM 密文及解密所需的非秘密参数、版本和更新时间写入当前浏览器的本地存储。只有成功解锁或同步后的资料才更新离线副本；网络断开后仍须使用原有查看凭证派生密钥解密。复制后的内容由用户自行管理剪贴板。

Service Worker 只缓存本仓库列出的静态网页资源，不拦截跨域同步后台，不缓存接口响应或管理员会话。网页资源完整保存后才显示离线已准备好。锁定和离开页面时清除内存会话与页面中的账号资料，保留加密副本以便下次解锁。

## 使用边界

这是小范围共享的轻量工具，尚未经专业安全审计。所有查看者共用一组凭证，无法逐人撤销已知的查看密码；查看者可以保存已解密的资料。忘记查看密码无法恢复已有资料。

旧版 GitHub 历史中的密文仍会保留。删除当前账号不会清除他人已复制的内容或历史副本；如业务凭证泄露，应在业务平台撤销或更换凭证。

仓库写入者可修改页面代码，因此仅授予可信人员写权限，不要添加来源不明的脚本。

## 开发与部署

前端无构建依赖；GitHub Pages 使用 main 分支根目录。修改页面后推送即可发布。

`backend/` 保存同步后台的源码副本。后台由 Sites 单独部署，GitHub Pages 不执行后台代码。后台环境变量在 Sites 中管理，不在仓库内；数据库迁移由 Drizzle 生成。具体说明见 `backend/README.md`。

加密测试：Node.js 22+ 执行 `npm test`。后台测试：Node.js 24 执行 `node --test backend/tests/*.test.mjs`。测试使用虚构数据，不写入线上密码库。
