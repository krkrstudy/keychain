# 钥匙串 · 本地私人版

站点：https://krkrstudy.github.io/keychain/

每台设备、每个浏览器或主屏幕应用拥有独立的密码库。资料在本地加密保存，不再调用旧版同步后台，也不再设置单独的管理员密码。

## 首次使用

1. 使用初始账号 `admin`、初始密码 `123456` 验证。
2. 必须设置 8—128 位新密码，并确认两次输入一致。
3. 设置完成后使用 `admin` 和新密码登录，即可添加、编辑、删除账号。

初始密码仅用于创建新的空密码库，不用于加密已有业务资料。初始化完成后，初始密码不能登录，也不能重建或覆盖现有密码库。账户名保持 `admin`。新密码仅用于当前设备中的密码库。

## 手机和离线使用

推荐 Safari 或 Chrome；微信内打开异常时选择“在浏览器打开”。页面显示“已准备好”后可添加到主屏幕。主屏幕应用首次打开时联网完成网页准备，之后可断网登录、查看、复制、新增、编辑和删除账号。

浏览器与主屏幕应用可能分别保存数据。不同设备不自动同步。网页升级后，原页面底部点击“更新网页”切换到新版；资料不会因网页升级而删除。

## 加密备份与旧版资料

登录后可“导出加密备份”。新设备初始化并登录后，选择“导入加密备份”，输入导出时使用的登录密码。备份中只保存密文及必要的格式、账号和时间信息，不保存业务账号明文或登录密码。

旧版保存的加密副本不会删除。如果当前浏览器中有旧版副本，会显示“导入旧版资料”；输入旧版查看密码后，在本设备解密并用当前新密码重新加密。也可导入单独交付的旧版加密备份。该备份不在 GitHub 仓库内。

导入采用合并：相同记录 ID 保留本地已有记录，其他记录追加；最多 1000 条。导入和修改密码均不会改变旧的备份文件。修改密码后，此前导出的备份仍使用导出时的密码。

浏览器清理站点数据、无痕模式关闭、系统回收、丢失设备等可能造成资料丢失。请定期导出加密备份。忘记密码不能恢复已有密文，初始密码不能作为恢复密码。

## 数据保护

沿用 AES-256-GCM 和 PBKDF2-SHA-256（600,000 次）加密方案，随机盐与 IV。新密码不保存，也不发送到服务器；密钥仅保存在当前页面内存中。IndexedDB 只保存加密密码库。读写使用事务与版本比较，拒绝其他窗口更新后的过期写入，不静默覆盖。

5 分钟无操作、离开页面或点击“锁定”会清除页面中的账号资料和内存会话。业务资料通过 textContent 显示，不作为 HTML 执行。剪贴板内容由设备系统管理。

Service Worker 仅缓存固定的静态网页资源，完整下载后才启用新缓存。新版页面限制连接来源为本站，业务资料不发送到任何同步接口。`backend/` 仅保留旧版后台源码，当前前端不调用该后台，也没有取消旧后台的管理授权保护。

## 开发与发布

无构建依赖，GitHub Pages 从 main 分支根目录发布。每次修改静态资源需要递增 `sw.js` 中缓存版本；新资源完整缓存后提示更新，用户点击后锁定并重新加载。失败的更新保留已完整下载的旧版本。

Node.js 22+：`node --test tests/*.test.js`。浏览器验证覆盖初始化强制改密、初始密码失效、离线 CRUD、备份导入导出、旧版迁移、密码修改、自动锁定、多窗口冲突、每台设备独立与 Safari/Chrome 兼容性。测试使用虚构资料，不修改线上私人密码库。
