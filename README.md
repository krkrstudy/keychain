# 钥匙串

一个部署在 GitHub Pages 的简洁共享密码库。普通查看者使用共享账号和解锁密码查看资料；管理员额外使用 GitHub 仓库写入授权，添加、编辑、删除条目。支持手机、复制、刷新同步和 5 分钟无操作自动锁定。

站点：https://krkrstudy.github.io/keychain/

## 使用

1. 使用管理员通过私下渠道提供的账号和登录密码解锁。
2. 普通查看者只能查看、显示和复制账号密码；点击“刷新”获取最新资料。
3. 管理员点击“管理员”，输入由本人在 GitHub 创建的 Fine-grained personal access token：仅选择 `krkrstudy/keychain`，授予 `Contents: Read and write`。设置合适有效期，不要把令牌分享给查看者。
4. 添加、编辑或删除后，浏览器加密整个密码库并提交到 GitHub。其他设备刷新列表即可读取，无需等待 Pages 重新发布。
5. 结束后点击“锁定”。刷新网页也会清除会话。

初始登录信息单独交付，不在仓库内。站点没有默认公开密码，也不会允许访客抢先初始化管理员。

## 保存与权限

- 使用浏览器 Web Crypto：PBKDF2-SHA-256（600,000 次）、随机 16 字节盐、AES-256-GCM、每次写入随机 12 字节 IV。
- 用户名和解锁密码共同参与密钥派生。共享登录并不是独立用户账户体系。
- `vault.json` 中只有密文；账号名称、账号、业务密码均在加密内容中。网站源码和密文仓库公开。
- 登录密码、解密密钥、管理员令牌不写入 localStorage、sessionStorage 或 Cookie。业务明文只在已解锁页面内存和用户主动复制的剪贴板中出现。
- 读取使用 GitHub 公共 API，修改必须通过 GitHub 服务端的权限校验。前端隐藏按钮不是权限边界。管理员令牌仅通过 HTTPS 发给 `api.github.com`，不提交到仓库。
- 并发写入使用文件 SHA 检查冲突，不静默覆盖其他管理员更新；冲突时先刷新再修改。

## 使用边界

这是小范围共享的轻量工具，并非经过专业安全审计的企业密码管理器。所有查看者共用一组凭证，无法逐人撤销访问。查看者可保存已经解密的资料。GitHub 历史中保留旧密文：删除条目不等于删除历史；即使以后更换解锁密码，旧密码仍能解密旧历史，需要撤销泄露的业务账号凭证。丢失解锁密码无法恢复。

仓库管理员可修改页面代码，因此仅授予可信人员写权限，不要添加来源不明的脚本。请使用随机强密码。受 GitHub API 可用性和限流影响，网络失败会明确报错；页面不会声称未成功的写入已经保存。多设备采用手动刷新同步。

## 部署

无外部脚本、无依赖构建。GitHub Pages 使用 main 分支根目录。`.nojekyll` 让静态文件直接发布。初始化时必须先在本地生成密文并私下交付登录信息，禁止将明文凭证推送到仓库。修改仓库路径时同时更新 `app.js` 中的固定 API 地址。

本地预览：`python3 -m http.server 4173`，打开 `http://localhost:4173/`。加密测试：Node.js 22+ 执行 `npm test`。测试使用虚构数据，不写入实际密码库。
